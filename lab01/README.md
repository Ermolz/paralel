устойчивая работа на 1024 не подтверждена. Все попытки включены в отчёт.

Для полного повторения исследования с формированием нового отчёта:

```bash
./lab all
```

Это занимает несколько минут и временно создаёт сотни Java-процессов.
Сценарий контролирует память, ограничивает длительность каждого запуска
и завершает только собственные процессы исследования.

```bash
./lab 7             # собственный HelloWorld
```

Если файловая система не позволяет выполнить `./lab`, используй `bash lab`.
Из Windows можно сначала войти в Ubuntu командой `wsl -d Ubuntu-24.04`.

## Методика исследования

В каждой попытке меняются **и slots, и число процессов `-np`**:
16, 32, 64, 128, 256, 512, 1024. Если найден отказ, сценарий проверяет
промежуточные значения, а затем повторяет проверку границы.
Успех означает код завершения 0 и наличие всех рангов `0..N-1` ровно один раз.
Перед выводом собственная программа выполняет MPI-барьер: все процессы
должны одновременно дойти до этой точки.

`slots` — вместимость запуска MPI-процессов, а не число физических ядер.
Процессор этого компьютера имеет 8 физических ядер и 16 аппаратных потоков.
Сотни MPI-процессов делят между собой эти вычислительные ресурсы.

Одинаковый профиль `capacity` используется в обычном запуске и исследовании:

```text
Java: -Xms4m -Xmx16m -Xss256k -Xint -XX:+UseSerialGC
      -XX:ActiveProcessorCount=1 -XX:-UsePerfData
MPI:  --oversubscribe --bind-to none --mca mpi_yield_when_idle 1
      --mca btl_vader_segment_size 1048576
```

Это настройки для небольшого HelloWorld и исследования числа процессов.
`-Xint` отключает JIT-компиляцию, поэтому измеренное время не является тестом
производительности численных алгоритмов. `ActiveProcessorCount=1` регулирует
внутренние пулы JVM и не меняет количество ядер компьютера.

Каждой попытке даётся 240 секунд. Защитный резерв — 1 ГиБ суммы доступной RAM
и свободного swap. Статус `MEMORY_GUARD` означает защитную остановку,
а не доказанный аппаратный предел. В сохранённых ранних пробах защита учитывала
только RAM; итоговые проверки используют также уже настроенный swap.
Если 1024 проходят, корректный вывод — «достигнута верхняя граница задания»;
абсолютный максимум за пределами 1024 не исследуется.

Для отдельных значений или сравнения с обычными настройками Java:

```bash
./lab research --counts 16 32 64
./lab research --profile default --counts 16 32
```

Новая серия обновляет последний отчёт, а предыдущие журналы сохраняются
в отдельных каталогах `results/runs/`. Рабочий `hostfile` восстанавливается
после завершения исследования.

## Повторная установка OpenMPI

В новой Ubuntu предварительно установи инструменты:

```bash
sudo apt-get update
sudo apt-get install -y openjdk-21-jdk build-essential maven curl ca-certificates python3
bash ../scripts/setup-openmpi.sh
source ../scripts/env.sh
```

OpenMPI 4.1.6 собирается в домашнем каталоге WSL, затем `mpi.jar` копируется
в локальный проект. Сценарий проверяет контрольную сумму исходного архива.
Логи установки: `../logs/config.out`, `../logs/make.out`, `../logs/install.out`.

Официальная документация: [OpenMPI 4.1](https://www.open-mpi.org/software/ompi/v4.1/),
[mpirun и slots](https://www.open-mpi.org/doc/v4.1/man1/mpirun.1.php),
[параметры Java 21](https://docs.oracle.com/en/java/javase/21/docs/specs/man/java.html).
