По [заданию](../Labs.pdf) требуется решить случайную систему линейных уравнений `A·X=B`, распределив расширенную матрицу между квадратной сеткой MPI-процессов. Обязательны коммуникаторы каждой строки и каждого столбца сетки и проверка ответа подстановкой. В нашей реализации используется метод Гаусса—Жордана с ведущими элементами на диагонали. Весь алгоритм находится в одном [GaussJordan.java](src/main/java/com/mathpar/NAUKMA/stud2026/GR03/yermolovych/GaussJordan.java), потому что это одна законченная задача с несколькими вспомогательными методами.

## 1 Идея задачи и параллельного решения

### Что означает система A X равно B

`A` — квадратная матрица коэффициентов размера `N×N`, `X` — неизвестный вектор длины `N`, `B` — известная правая часть. Каждая строка матрицы задаёт одно уравнение:

```text
A[i][0]·X[0] + A[i][1]·X[1] + ... + A[i][N-1]·X[N-1] = B[i]
```

Для преобразований удобно хранить правую часть дополнительным столбцом: `[A | B]`. Размер такой расширенной матрицы — `N×(N+1)`. Операции над строкой должны применяться и к коэффициентам, и к правой части, иначе получится другая система.

Задание допускает метод Гаусса или Гаусса—Жордана. Здесь выбран второй: он последовательно превращает левую часть в единичную матрицу. Тогда справа остаются значения неизвестных, то есть `[A | B]` превращается в `[I | X]`.

### Как работает один шаг Гаусса Жордана

На шаге `s` ведущий элемент берётся с диагонали: `pivot=A[s][s]`. Ведущая строка делится на этот элемент, поэтому её диагональный коэффициент становится единицей. Затем для любой другой строки `i` из неё вычитается нормированная ведущая строка, умноженная на прежнее значение `A[i][s]`.

```text
нормированная строка: R[s] = R[s] / pivot
для i != s:          R[i] = R[i] - oldA[i][s]·R[s]
```

В позиции `s` каждой другой строки получается ноль. Преобразования выполняются и выше, и ниже диагонали. Поэтому после последнего шага не нужен отдельный обратный ход для вычисления неизвестных.

Небольшой учебный пример для понимания:

```text
2x + y  = 5            [ 2  1 | 5 ]
 x + 3y = 5            [ 1  3 | 5 ]

Первую строку делим на 2:
[ 1  0.5 | 2.5 ]
[ 1  3   | 5   ]

Из второй вычитаем первую:
[ 1  0.5 | 2.5 ]
[ 0  2.5 | 2.5 ]

Вторую делим на 2.5, затем убираем 0.5 в первой:
[ 1  0 | 2 ]
[ 0  1 | 1 ]
```

Получаем `x=2`, `y=1`. В программе выполняются те же операции, но отдельные участки каждой строки находятся в разных процессах. Этот пример объясняет математику; он не является записанным запуском программы со случайной матрицей.

### Ограничение диагонального выбора

В этой лабораторной используется наивный вариант: ведущие элементы остаются на диагонали, строки и столбцы не переставляются. После предыдущих исключений очередной диагональный элемент может стать нулевым или слишком малым даже у системы, для которой другой порядок строк позволил бы продолжить решение.

Код проверяет конечность ведущего элемента и условие `abs(pivot)>1e-12`. Если оно не выполнено, вычисление прекращается. Эта проверка предотвращает деление на недопустимый ведущий элемент, но не добавляет поиск другого элемента и не является оценкой невязки готового ответа.

### Сетка процессов и размеры блоков

Обозначения важно не смешивать:

| Обозначение | Смысл |
| --- | --- |
| `processes` | Общее число MPI-процессов. |
| `n` | Число процессов в одной строке и одном столбце сетки. |
| `N`, в коде `order` | Число уравнений и неизвестных. |
| `k` | Число строк и основных столбцов одного блока, `k=N/n`. |

Требуется `processes=n*n` и `N=k*n`. Процессы образуют логическую сетку `n×n`; она не описывает физическое расположение процессорных ядер. Один ранг отвечает за один блок расширенной матрицы.

Обычный блок содержит `k×k` коэффициентов. Блоки последнего столбца сетки дополнительно хранят по одному столбцу правой части, поэтому их размер `k×(k+1)`. Правая часть распределена по строкам вместе с соответствующими коэффициентами.

Например, при четырёх процессах и `N=4` получаются `n=2`, `k=2`:

| Мировой ранг | Координаты блока | Строки исходной матрицы | Столбцы и ширина |
| --- | --- | --- | --- |
| 0 | `(0,0)` | 0–1 | Коэффициенты 0–1, ширина 2. |
| 1 | `(0,1)` | 0–1 | Коэффициенты 2–3 и `B`, ширина 3. |
| 2 | `(1,0)` | 2–3 | Коэффициенты 0–1, ширина 2. |
| 3 | `(1,1)` | 2–3 | Коэффициенты 2–3 и `B`, ширина 3. |

Каждый процесс изменяет свой локальный блок. Передача ведущей строки означает передачу её отдельных фрагментов, потому что вся строка изначально разделена между процессами.

### Зачем нужны коммуникаторы строк и столбцов

Для обновления локального прямоугольника нужны два разных набора данных. Для каждой его строки требуется коэффициент исключения `oldA[i][s]`, находящийся в блоке ведущего столбца. Для каждого его столбца требуется значение нормированной ведущей строки, находящееся в блоке ведущей строки.

Коэффициенты удобно передавать горизонтально по процессам одной строки сетки. Фрагменты ведущей строки — вертикально по процессам одного столбца сетки. Поэтому программа создаёт оба вида коммуникаторов и использует `bcast` в нужном направлении.

`split(color,key)` группирует процессы с одинаковым `color`, а `key` задаёт их порядок внутри новой группы. Для строк используется `split(blockRow,blockColumn)`: цветом является строка сетки, локальный ранг совпадает с координатой столбца. Для столбцов — `split(blockColumn,blockRow)`, поэтому локальный ранг совпадает с координатой строки.

В примере на четырёх процессах коммуникаторы строк содержат `{0,1}` и `{2,3}`, столбцов — `{0,2}` и `{1,3}`. Корень `bcast` задаётся локальным рангом внутри выбранного коммуникатора. Поэтому номер владельца блочной строки или столбца можно непосредственно использовать как номер корня нужной рассылки.

### Что программа считает ошибкой решения

После получения `X` процесс 0 подставляет его в исходные уравнения:

```text
P[i] = Σ A[i][j]·X[j] - B[i]
error = max_i abs(P[i])
```

`P` называется вектором невязки, а вычисленный максимум — его бесконечной нормой. Он показывает, насколько полученный ответ удовлетворяет исходным уравнениям. В программе используется именно формула проверки из задания.

Это абсолютная невязка, а не относительная ошибка и не прямое расстояние до неизвестного точного решения. Небольшая невязка полезна для проверки, но у плохо обусловленной системы сама по себе не гарантирует столь же маленькую ошибку в компонентах `X`. Из-за округления `double` даже правильное решение обычно даёт малые ненулевые значения `P`.

## 2 Как работает код и что рассказывать на защите

### Карта методов одного файла

```text
main
  → MPI.Init
  → run
      → проверка параметров
      → создание rowComm и columnComm
      → создание исходной матрицы на ранге 0
      → distribute
      → eliminate
      → collectSolution
      → вычисление невязки на ранге 0
      → bcast общего статуса завершения
      → free коммуникаторов
  → MPI.Finalize
  → при ошибке System.exit
```

Эту последовательность выполняет каждый процесс. Вызов `distribute` на ранге 0 не запускает Java-метод у других рангов: они сами уже выполняют свою копию программы и входят в тот же метод, где выбирают ветку приёма.

### main Инициализация и код завершения

`main` вызывает `MPI.Init(args)` и передаёт управление `run(args)`. Метод `run` возвращает целочисленный результат: 0 при нормальном завершении, 2 при ошибке параметров, 1 при вычислительной ошибке, которую обнаруживает алгоритм.

`MPI.Finalize()` находится в `finally` и выполняется перед возможным `System.exit(exitCode)`. Завершение MPI и завершение Java-процесса оформлены отдельно. Логика вычислений находится в `run` и его вспомогательных методах.

### run Параметры и подготовка сетки

Каждый процесс получает `rank` и `processes`, вычисляет `n=(int)Math.sqrt(processes)`, затем проверяет `n*n==processes`. Округлённого квадратного корня без этой проверки недостаточно: три процесса, например, нельзя представить квадратной сеткой нужного вида.

Программа принимает не более двух собственных аргументов: `N` и `seed`. По умолчанию это 4 и 2026. Размер должен быть положительным и делиться на `n`. Все процессы получают одинаковые аргументы и при некорректном варианте возвращают код 2; сообщение печатает только ранг 0.

Координаты блока вычисляются как `blockRow=rank/n`, `blockColumn=rank%n`. Затем задаётся `width=k` или `k+1` для последнего столбца и создаются два коммуникатора через `split`.

Только ранг 0 выделяет `original[N][N+1]`. Генератор `Random(seed)` заполняет все коэффициенты и правую часть по формуле `1.0+99.0*nextDouble()`. Фактический диапазон — от 1 включительно до 100 не включительно, что удовлетворяет границам задания. Один `seed` воспроизводит те же входные данные.

`original` сохраняется без исключений и нормирования для будущей проверки невязки. Следовательно, численная работа распределена по блокам, но исходная полная матрица дополнительно хранится на корне. Это важно учитывать, если обсуждается расход памяти.

### distribute Раздача локальных прямоугольников

Каждый процесс создаёт одномерный `double[]` длиной `k*width`. Локальная матрица хранится построчно: элемент строки `i`, столбца `j` расположен по индексу `i*width+j`. У последнего столбца `width=k+1`, поэтому использовать в этом выражении всегда `k` было бы ошибкой.

Процесс 0 циклом перебирает адресатов. Для каждого вычисляет начало глобальных строк `(destination/n)*k`, начало столбцов `(destination%n)*k` и ширину блока. `System.arraycopy` копирует `k` коэффициентов каждой строки; для последнего столбца отдельно дописывается значение `original[row][N]`, то есть правая часть.

Блок адресата 0 остаётся локальным. Остальные отправляются одним массивом `MPI.DOUBLE` с тегом 10. На других рангах уже выполняется соответствующий `recv` от источника 0. После завершения метода каждый располагает именно своим прямоугольником, а полный `original` остаётся только у корня.

### eliminate Владелец ведущего элемента

Метод выполняет `order` шагов, `step=0 ... N-1`. Для каждого шага вычисляются:

```text
owner = step / k
localIndex = step % k
```

`owner` — номер блочной строки и блочного столбца диагонального элемента. `localIndex` — его позиция внутри блока. Ведущий элемент физически хранится на мировом ранге `owner*n+owner`.

Для `N=4`, `k=2` первые два ведущих элемента принадлежат рангу 0, следующие два — рангу 3. На шаге 2 получаются `owner=1`, `localIndex=0`: используется первая диагональная позиция внутри правого нижнего блока.

### eliminate Передача ведущего элемента всем процессам

Ведущий процесс считывает `block[localIndex*width+localIndex]` в однокомпонентный массив `pivot`. Далее обмен идёт двумя этапами:

1. Только процессы блочной строки `owner` вызывают `rowComm.bcast(pivot,...,owner)`. Теперь каждый процесс этой строки знает ведущий элемент.
2. Все процессы вызывают `columnComm.bcast(pivot,...,owner)`. В каждом столбце источником является участник из блочной строки `owner`, который только что получил значение.

В результате один скаляр распространяется от диагонального владельца по его строке, затем по всем столбцам. Это не вызов на `COMM_WORLD`: используются созданные подкоммуникаторы и локальные номера корня.

После рассылок все имеют один и тот же `pivot` и выполняют одинаковую проверку его допустимости. При непригодном значении все возвращают `false` из `eliminate`, поэтому никто не должен продолжить к следующим рассылкам этого метода.

### eliminate Передача коэффициентов исключения

Процессы из блочного столбца `owner` имеют нужный глобальный столбец `step`. Они копируют `k` его значений в `factors[i]=block[i*width+localIndex]`. Затем каждая строка сетки выполняет `rowComm.bcast(factors,...,owner)`.

Теперь все блоки одной блочной строки знают одинаковые коэффициенты для своих `k` глобальных строк. Коэффициенты сохраняются до деления ведущей строки и до обновлений: в формуле исключения нужны прежние значения `A[i][step]`.

Каждый процесс хранит только `k` коэффициентов своей блочной строки. Рассылать всем полный столбец из `N` значений для этой реализации не требуется.

### eliminate Нормирование и передача ведущей строки

Все процессы блочной строки `owner` владеют разными частями одной глобальной ведущей строки. Каждый делит свою местную строку с индексом `localIndex` на `pivot[0]` и записывает полученный фрагмент в `pivotRow`.

Затем выполняется `columnComm.bcast(pivotRow,width,MPI.DOUBLE,owner)`. В каждом столбце вниз и вверх передаётся только соответствующий фрагмент ведущей строки. Последний столбец передаёт `k+1` значений, остальные — `k`; внутри каждого отдельного столбцового коммуникатора ширина у всех участников одинакова, поэтому параметры рассылки согласованы.

Здесь становится видно назначение двух направлений: `factors` приходят по строке процессов, `pivotRow` — по столбцу. После двух рассылок у каждого есть всё для обновления своего прямоугольника.

### eliminate Локальное обновление блока

Каждый процесс перебирает локальные строки `i` и столбцы `j` и выполняет:

```java
block[i * width + j] -= factors[i] * pivotRow[j];
```

Если глобальный номер строки `blockRow*k+i` совпадает с `step`, обновление пропускается: это уже нормированная ведущая строка. В блоках ведущего столбца соответствующие исключённые позиции дополнительно явно записываются как `0.0`.

Правая часть находится внутри тех же циклов как последний локальный столбец, поэтому преобразуется согласованно с коэффициентами. После обновления начинается следующий шаг. Явный общий `barrier` на каждой итерации не требуется: нужные зависимости выражены порядком блокирующих коллективных обменов и последующих вычислений.

Арифметика внутри одного шага выполняется параллельно на локальных блоках. Сами шаги зависят друг от друга: следующий ведущий элемент выбирается из матрицы после предыдущего исключения. Нельзя просто запустить все `N` шагов независимо.

### Пример направления обменов на шаге 2

Для сетки 2×2 и `N=4` шаг 2 принадлежит рангу 3. Сначала он передаёт ведущий элемент рангу 2 по нижней строке. Затем нижние участники столбцов распространяют его вверх: 2 → 0 и 3 → 1.

Коэффициенты столбца 2 находятся в правом столбце процессов: ранг 1 передаёт свою пару рангу 0, ранг 3 — рангу 2. Нормированные фрагменты ведущей строки находятся в нижней строке: ранг 2 передаёт левый фрагмент рангу 0, ранг 3 — правый фрагмент с правой частью рангу 1.

После этого каждый обновляет свой блок. Такие стрелки описывают логическое распространение данных через `bcast`, а не обязательную внутреннюю реализацию MPI для произвольной большой группы.

### collectSolution Сбор последнего столбца

После исключения коэффициентная часть соответствует единичной матрице, а решение находится в преобразованной правой части. Её элементы лежат только у процессов последнего блочного столбца.

Каждый такой процесс копирует `k` значений из `block[i*width+k]` в `part`. Затем участники последнего `columnComm` выполняют `gather` на локальный корень 0. Локальная нумерация идёт по блочным строкам, поэтому фрагменты собираются в порядке неизвестных.

Мировой ранг этого корня — `n-1`: верхний участник последнего столбца. Если `n>1`, он отправляет собранный вектор мировому процессу 0 с тегом 20. Процесс 0 принимает его от `n-1`. Остальные столбцы не участвуют в этом `gather`, потому что он вызван на коммуникаторе последнего столбца.

При `n=1` единственный процесс одновременно является последним столбцом и мировым корнем. Он получает результат локально, а лишние `send/recv` пропускаются.

### run Проверка ответа и завершение

Вернувшийся из `collectSolution` вектор используется на ранге 0. Корень перемножает сохранённую исходную `A` с найденным `X`, вычитает исходную `B` и находит максимум модулей. Использовать изменённую матрицу после исключения для такой проверки было бы неверно: нужно проверить исходную систему.

При `N<=12` печатаются входная расширенная матрица, весь `X` и весь `P`. Для более крупных размеров остаётся итоговая ошибка, чтобы вывод не занимал тысячи строк. Если ошибка не является конечным числом, устанавливается ненулевой статус.

Затем статус рассылается через `MPI.COMM_WORLD.bcast`, чтобы участники завершили расчёт согласованно. В `finally` метода `run` освобождаются оба созданных коммуникатора. После возврата в `main` выполняется `MPI.Finalize`.

В сохранённом и повторно проверенном примере на четырёх процессах с `N=4`, `seed=2026` напечатана невязка `7.105427357601e-15`. Для девяти процессов, `N=6`, `seed=42` — `2.273736754432e-13`. Это результаты конкретных входов, не гарантированная верхняя граница ошибки для любых случайных систем.

### Как построить рассказ на защите

Начать можно так: «Я решаю систему методом Гаусса—Жордана с диагональными ведущими элементами. Расширенная матрица разделена на блоки квадратной сетки процессов. Для каждого шага коэффициенты исключения распространяются по строкам сетки, а нормированная ведущая строка — по столбцам. После локальных обновлений собираю решение и проверяю его на исходной матрице».

Далее покажи порядок методов в `run`. На стандартном примере вычисли `n=2`, `k=2`, нарисуй четыре блока и объясни дополнительный столбец `B`. В `eliminate` последовательно покажи `owner`, рассылку `pivot`, сохранение `factors`, рассылку `pivotRow` и формулу обновления. Заверши переходом от последнего столбца процессов к полному решению и формулой невязки.

Команды из корня проекта:

```bash
cd ~/paralel
./lab lab09
./lab lab09 9 6 42
```

Формат команды — `./lab lab09 [processes] [N] [seed]`. Скрипт передаёт первый параметр `mpirun`, а Java-класс получает только `N` и `seed`. Полная команда Java-запуска и фактический вывод находятся в комментарии исходника, остальные сохранённые примеры — в [results](results/).

Если спросят, почему один файл, покажи одну задачу и четыре вспомогательных метода вокруг `main`. Если спросят, зачем два коммуникатора, объясни два направления доставки данных для локального обновления. Если спросят, почему нет обратного хода, укажи обнуление и выше, и ниже диагонали. Если спросят, что доказывает маленькая ошибка, назови удовлетворение исходным уравнениям с малой абсолютной невязкой.

Объём арифметики классического метода растёт примерно как `N³`. Блочное разбиение распределяет эту работу, но остаются последовательные шаги, рассылки и централизованные подготовка и сбор. Маленькие демонстрационные запуски предназначены для объяснения правильности; они сами по себе не показывают ускорение от добавления MPI-процессов.
