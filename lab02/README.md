# Лабораторная 2 — коммуникаторы

Yermolovych, группа 03, 2026.

- `EvenRanksCommunicator.java` — группа чётных рангов `0, 2, 4...`,
  отдельный коммуникатор через `createGroup`; нечётные ранги исключаются.
- `MatrixCommunicator.java` — группа первых 15 процессов (`0..14`),
  её базовый коммуникатор и декартова сетка **3×5** без замыкания краёв.
  Включено `reorder=true`. Остальные процессы выводят `excluded from matrix 3x5`.

Run:

```bash
cd ~/paralel
./lab lab02
```

Общий запуск выполняет первый пример на 8 процессах, второй — на 16.
Отдельные команды:

```bash
./lab lab02 even 8
./lab lab02 matrix 16
./lab lab02 matrix 15
```

Для матрицы нужны минимум 15 MPI-процессов. При меньшем числе программа
печатает сообщение и завершает MPI. Это число процессов, а не физических ядер;
локальный запуск использует `--oversubscribe`. Если количество передано явно
для `all`, оно применяется к обоим примерам: `./lab lab02 all 16`.

`getGroup` получает описание группы, `incl` выбирает ранги, `createGroup`
создаёт коммуникатор. Эта операция коллективная для участников выбранной группы;
невключённые процессы в данном примере тоже вызывают её и получают пустой
коммуникатор. В Java его проверяют через `isNull()`, а не сравнением с `null`.

`CartComm` и `ShiftParms` используют правильные имена классов.
`createCart` задаёт топологию, `getCoords` возвращает координаты, `shift`
определяет соседей. `shift` сам не передаёт данные. Соседи указаны рангами
декартового коммуникатора; `none` соответствует `MPI.PROC_NULL` на границе.
`reorder=true` разрешает перенумерацию, поэтому нельзя в общем случае считать
глобальный и матричный ранг одинаковыми. В проверенных запусках порядок сохранился.

Вручную проверены чётные группы на 1, 7 и 8 процессах, матрица на 15 и 16,
а также сообщение о недостаточном числе участников на 14 процессах.
Новые выводы находятся в `results/even-create-group-*.txt` и
`results/matrix-3x5-*.txt`. Прежние результаты сохранены и относятся к старой версии.
