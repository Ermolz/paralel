# Лабораторная 11

Сравнение алгоритмов лабораторных 9 и 10 в самостоятельном файле
`GaussJordanComparison.java`:

- `DIAGONAL` — Гаусс—Жордан с диагональными ведущими элементами.
- `ALL_GATHER` — полный выбор с обменом максимумами между всеми процессами.
- `ROW_COLUMN` — полный выбор с обменом через строки и последний столбец сетки.

В обоих экспериментах `A` имеет размер **2048×2048** (`2K = 2048`),
расширенная матрица `[A | B]` — **2048×2049**. Элементы генерируются
как `1 + 99 * Random.nextDouble()`, `seed = 2026`.
Все методы получают свежие копии одной и той же матрицы.
Используются отдельные коммуникаторы строк и столбцов, блоки `k×k`
и `k×(k+1)` в последнем столбце, как в лабораторных 9–10.

Run:

```bash
cd ~/paralel
./lab lab11
```

Эта команда показывает сохранённые результаты обоих экспериментов.
Для короткого живого примера: `./lab lab11 demo`.
Для повторного выполнения исследований:

```bash
./lab lab11 accuracy
./lab lab11 time
```

Ручная проверка выполнена без автоматических тестов. Малый пример `N=4`
совпал с результатами лабораторных 9–10; сетка из 64 процессов дополнительно
проверена на `N=8`. Тяжёлые исследования из-за оформления комментариев не повторяются.

Измерения выполнены 2026-09-22: Intel Core i7-6900K, 8 физических ядер,
16 логических процессоров; Ubuntu 24.04 в WSL, Java 21.0.12, OpenMPI 4.1.6.

Для точности используются **64 MPI-процесса**, сетка `8×8`, `k=256`,
с эмуляцией через `--oversubscribe`. Сравнивается невязка
`max(abs(A * X - B))` по исходной системе. Это не прямое измерение ошибки
относительно точного решения `X`. Время этой эмуляции не используется
для сравнения производительности.

| Метод | Невязка на 64 процессах |
| --- | ---: |
| DIAGONAL | 8.255898528375e-06 |
| ALL_GATHER | 1.738058585943e-10 |
| ROW_COLUMN | 1.738058585943e-10 |

Для этой матрицы полный выбор уменьшил невязку примерно в **47 500 раз**.
Два способа обмена максимумами дали одинаковую невязку.

Для времени используются **4 MPI-процесса на четырёх разных физических ядрах**,
сетка `2×2`, `k=1024`, без переподписки. Число процессов выбрано из допустимых
заданием 4, 9 и 16: физических ядер этого компьютера достаточно для 4.
Выполняются пять прогревочных запусков и пять измерений каждого метода,
порядок методов циклически меняется. После `barrier` измеряется `MPI.wtime`,
берётся максимум длительности по процессам, затем медиана пяти запусков.
В интервал входят поиск ведущих элементов, исключение и сбор решения;
генерация, распределение матрицы, копирование блоков, невязка и печать исключены.

Итоговая серия времени на четырёх процессах:

| Метод | Медиана, с | Диапазон пяти измерений, с |
| --- | ---: | ---: |
| DIAGONAL | 5.244522 | 5.017753–5.995133 |
| ALL_GATHER | 8.871788 | 8.254106–9.684816 |
| ROW_COLUMN | 8.458553 | 8.193955–10.374450 |

Невязки на 4 процессах совпали с невязками на 64 процессах.
На этой системе диагональный метод быстрее, а полный выбор даёт меньшую невязку.
Медиана `ROW_COLUMN` немного меньше, чем у `ALL_GATHER`, но диапазоны времени
перекрываются: устойчивое преимущество одного способа обмена не установлено.
Это результаты для одной случайной системы и данного компьютера.

Все выводы, даты запусков, сведения о среде и привязка к ядрам находятся
в `results/`. Для сдачи нужен только
`src/main/java/com/mathpar/NAUKMA/stud2026/GR03/yermolovych/GaussJordanComparison.java`.
Команды `Run:` и фактический `Terminal output:` находятся внутри Java-файла.

Первоначальная серия с двумя прогревами сохранена в `results/time-initial-*`.
В ней наблюдалось снижение времени по мере выполнения; итоговая серия
использует увеличенный прогрев.
