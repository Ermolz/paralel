Во всех программах используются `getRank()` и `getSize()`; ранг, размер
коммуникатора и содержимое массива видны в выводе. В книге второй пример
назван `TestISendAndIRecv`, хотя внутри используется `recv`; здесь названия
разделены по фактически вызываемым методам.

Java-файлы для сдачи: `src/main/java/com/mathpar/NAUKMA/stud2026/GR03/yermolovych/`.
Каждый файл содержит комментарий с командой и настоящим выводом терминала.

Запуск в Ubuntu / WSL:

```bash
cd ~/paralel
./lab lab03
./lab lab03 send 2
./lab lab03 isend 8
./lab lab03 irecv 8
```

`./lab lab03` запускает все три программы на восьми процессах.
Генератор `Random(2026)` создаёт повторяемые исходные массивы.
Порядок строк от разных процессов может меняться.

Все три программы проверены на 1, 2, 4 и 8 процессах: 12 успешных запусков.
Проверялись ранги, размеры коммуникаторов и совпадение всех элементов массива
у получателей с исходным массивом. Вывод сохранён в `results/`, итог проверки —
в `results/verification.txt`. При одном процессе выполняется только источник.

Для защиты: `getSize` возвращает размер коммуникатора, `getRank` — ранг в нём.
После `send` можно снова использовать буфер отправки; это не гарантирует,
что получатель уже завершил `recv`. После `recv` данные доступны получателю.
`iSend` и `iRecv` возвращают `Request`; завершение проверяется через `waitFor`.
В установленном OpenMPI неблокирующим вызовам нужен прямой буфер — здесь
`MPI.newIntBuffer`. Буфер не меняется до завершения отправок, а результат
приёма читается только после ожидания. Все запросы завершаются до `MPI.Finalize`.

Сдавать только три `.java`-файла. Скрипт, README и результаты остаются локально.
