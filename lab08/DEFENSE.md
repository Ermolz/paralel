## 1 Идея работы и распределение вычислений

### Из чего складывается параллельный алгоритм

В каждой программе процесс 0 создаёт исходные данные, выделяет независимые части работы и передаёт нужные части другим процессам. Они выполняют локальные вычисления и отправляют результаты. Процесс 0 также считает свою часть, после чего собирает общий ответ.

У каждого MPI-процесса своя JVM и память. Передача матрицы не делает её общим объектом: получатель работает с восстановленной локальной копией. Параллельность возникает из-за того, что после получения данных разные процессы могут независимо умножать свои блоки или строки.

Алгоритм должен ответить на три вопроса: какой кусок результата поручен процессу, какие входные данные ему нужны и куда вернуть ответ. MPI не определяет это за разработчика. В наших исходниках распределение задач видно в ветках по `rank`, массивах индексов блоков и параметрах отправок.

### Что дают классы Mathpar

| Класс | Роль в работе |
| --- | --- |
| `MatrixD` | Представление плотной матрицы в двух программах блочного умножения. |
| `MatrixS` | Представление матрицы со строками значений и индексами столбцов в примере матрицы и вектора. |
| `VectorS` | Вектор из математических элементов. |
| `NumberZ` | Целое число, в последнем примере — множитель 5. |
| `Element` | Общий тип математических значений Mathpar. |
| `Ring` | Описание области вычислений; у нас `Z[]`, то есть вычисления над целыми числами без переменных. |
| `MPITransport` | Передача объектов Mathpar через сериализацию и MPI. |

Обозначение `MatrixS` относится к способу представления матрицы. Исходная матрица в нашем примере при этом заполнена ненулевыми значениями: использование такого класса само по себе не делает данные разреженными.

Каждый процесс создаёт собственный `Ring("Z[]")`. Арифметические методы получают `ring`, чтобы выполнять операции в согласованной математической области. Входы фиксированы и целочисленны, поэтому результаты удобно проверять точно. В этой работе не исследуется накопление ошибок `double`.

### Как MPITransport передаёт математический объект

`MPITransport.sendObject` сериализует объект в байтовый массив и вызывает блокирующий `MPI.COMM_WORLD.send` с типом `MPI.BYTE`. `recvObject` сначала выполняет `probe`, узнаёт длину через `getCount(MPI.BYTE)`, принимает байты и восстанавливает объект через Java-десериализацию.

`sendObjectArray(objects, offset, count, destination, tag)` записывает в один поток `count` объектов, начиная с `offset`, и отправляет одно байтовое сообщение. Соответствующий `recvObjectArray` читает такое же число объектов и записывает их в переданный массив получателя. Это не операция `scatter` и не автоматическая отправка по одному объекту разным адресатам.

Таким образом, есть два уровня: наш код решает, какие матрицы и кому нужны, а транспорт переводит объекты в байты и обратно. Типы `MatrixD`, `MatrixS` и `VectorS` имеют смысл для Mathpar и Java, а нижележащий MPI-вызов переносит байты.

Локальные классы и зависимости находятся в [lib/mathpar](../lib/mathpar/README.md). Используются обычные блокирующие методы транспорта; методы библиотеки с префиксом `i` эти четыре программы не вызывают.

### Блочная формула умножения матриц

Разделим обе матрицы на четыре квадранта:

```text
A = [ A00  A01 ]       B = [ B00  B01 ]
    [ A10  A11 ]           [ B10  B11 ]
```

Тогда результат состоит из четырёх блоков:

```text
C00 = A00·B00 + A01·B10
C01 = A00·B01 + A01·B11
C10 = A10·B00 + A11·B10
C11 = A10·B01 + A11·B11
```

Это обычное правило умножения матриц, применённое к блокам. Для одного блока результата нужны два произведения и их сумма. Четыре блока результата независимы, если нужные исходные блоки уже доступны.

Можно поручить каждому из четырёх процессов сразу целый блок результата. Другой вариант — поручить каждому из восьми процессов одно произведение, а затем попарно сложить произведения. Именно эти две схемы реализованы в первых двух программах. Это разбиение одного уровня: наш код не вызывает себя рекурсивно.

### Умножение матрицы на вектор

Для строки с индексом `i` ответ равен `y[i]=Σ A[i][j]·b[j]`. Строки независимы: вычисление `y[i]` не требует результатов других строк. Поэтому матрица делится по строкам, а каждому исполнителю нужен весь исходный вектор.

Если процессов `p`, код задаёт `count=order/p` строк каждому ненулевому рангу и `rootCount=order-count*(p-1)` строк рангу 0. Корень получает обычную долю плюс остаток от деления. Так ни одна строка не теряется при неделимом размере.

### Умножение вектора на число

Каждый элемент результата равен `result[i]=b[i]·scalar`. Для него не нужны другие элементы, поэтому можно разделить вектор на последовательные фрагменты. Это наиболее простая схема распределения: раздать части, локально выполнить одинаковый цикл, вернуть части на прежние позиции.

В этой программе число 5 создаётся на каждом процессе непосредственно в коде. Его не пересылают с каждым фрагментом. Участникам заранее известны одинаковые `order`, правило разбиения и множитель.

## 2 Как работает код и что рассказывать на защите

### Общая структура и независимые запуски

Все четыре файла имеют собственный `main`. Скрипт `./lab lab08` последовательно запускает четыре MPI-программы. Первая требует ровно четыре процесса, вторая — восемь. Две векторные программы допускают другое число участников в пределах размера данных.

Общая цепочка: `MPI.Init` → определение роли по рангу → создание `Ring` → распределение данных → локальная арифметика → передача результатов → печать общего ответа → `MPI.Finalize`. Процесс 0 координирует обмены и тоже выполняет арифметику.

### MatrixMul4 Один блок результата на процесс

Исходник: [MatrixMul4.java](src/main/java/com/mathpar/NAUKMA/stud2026/GR03/yermolovych/MatrixMul4.java).

Процесс 0 создаёт две фиксированные матрицы 4×4. `splitTo4()` разбивает каждую на четыре блока 2×2 в порядке: верхний левый, верхний правый, нижний левый, нижний правый. Поэтому индексы 0, 1, 2, 3 соответствуют обозначениям 00, 01, 10, 11.

Метод `mmultiply(a,b,c,d,ring)` вычисляет `a·b+c·d`. Он вызывает арифметические методы `multCU` и `add`; MPI-вызовов внутри него нет. Распределение вычислений задаёт вызывающий `main`.

| Ранг | Переданные блоки или локальные данные | Вычисляемый блок |
| --- | --- | --- |
| 0 | `aa[0], bb[0], aa[1], bb[2]` | `C00` |
| 1 | `aa[0], bb[1], aa[1], bb[3]` | `C01` |
| 2 | `aa[2], bb[0], aa[3], bb[2]` | `C10` |
| 3 | `aa[2], bb[1], aa[3], bb[3]` | `C11` |

Ранг 0 отправляет каждому работнику один массив из четырёх объектов. Вызов с параметрами `0,4,destination,tag` означает смещение 0, четыре объекта, адресата и тег. Тег равен рангу адресата.

Работник создаёт `Object[4]`, вызывает `recvObjectArray(..., 0, rank)`, приводит элементы к `MatrixD` и передаёт их в `mmultiply`. Полученный блок отправляется обратно рангу 0 с тегом собственного ранга.

Корень считает `blocks[0]` сам, затем принимает `blocks[1]`, `blocks[2]`, `blocks[3]` от соответствующих источников. `MatrixD.join(blocks)` размещает их обратно по квадрантам. Приём в фиксированном порядке задаёт порядок записи результата, но не означает, что вычисления работников шли по очереди.

```text
rank 0: splitTo4 → sendObjectArray работникам → mmultiply своего блока
        → recvObject трёх блоков → MatrixD.join → печать
rank 1–3: recvObjectArray → mmultiply → sendObject результата
```

Для проверки первого элемента полного ответа достаточно вычислить `1·2+2·1+3·3+4·0=13`. В сохранённом результате первая строка равна `[13,15,11,13]`. Здесь вычисляются произведения матриц, не поэлементное умножение одинаковых позиций.

### MatrixMul8 Одно частичное произведение на процесс

Исходник: [MatrixMul8.java](src/main/java/com/mathpar/NAUKMA/stud2026/GR03/yermolovych/MatrixMul8.java).

Матрицы имеют размер 8×8. Их элементы задаются формулами `A[i][j]=8*i+j+1` и `B[i][j]=i+j+1`. После `splitTo4` размер каждого блока — 4×4.

Массивы `left` и `right` показывают, какие блоки умножает каждый ранг. Полная схема:

| Ранг | Локальное произведение | Куда идёт результат |
| --- | --- | --- |
| 0 | `A00·B00` | Складывает с результатом ранга 1 и получает `C00`. |
| 1 | `A01·B10` | Рангу 0. |
| 2 | `A00·B01` | Складывает с рангом 3, затем отправляет `C01` рангу 0. |
| 3 | `A01·B11` | Рангу 2. |
| 4 | `A10·B00` | Складывает с рангом 5, затем отправляет `C10` рангу 0. |
| 5 | `A11·B10` | Рангу 4. |
| 6 | `A10·B01` | Складывает с рангом 7, затем отправляет `C11` рангу 0. |
| 7 | `A11·B11` | Рангу 6. |

Процесс 0 отправляет каждому другому рангу два объекта с тегом 0. Все работники получают их от источника 0 и выполняют одно `multCU`. Нечётный ранг отправляет произведение рангу `rank-1`. Чётные работники 2, 4, 6 сначала получают произведение от `rank+1`, складывают его со своим и отправляют сумму корню. Все эти результаты передаются с тегом 3.

Одинаковый тег результатов не создаёт неоднозначности: принимающий код явно задаёт источник. Например, ранг 2 ждёт сообщение от 3, а корень — от 1, 2, 4 и 6 для соответствующих стадий. Входные данные и результаты также различаются направлением и тегом.

На ранге 0 особая ветка: он складывает своё произведение с частичным результатом ранга 1, затем принимает уже готовые блоки от 2, 4, 6. После этого `MatrixD.join` собирает полную матрицу.

На защите объясни, что восемь процессов выполняют те же восемь блочных произведений, которые в четырёхпроцессной схеме распределены по два на исполнителя. Общее арифметическое содержание остаётся прежним, добавляется попарная передача промежуточных результатов. Из самого количества процессов не следует двукратное ускорение. Кроме того, стандартные демонстрации используют разные размеры матриц, поэтому по ним нельзя непосредственно сравнивать производительность.

### MultiplyMatrixToVector Распределение строк

Исходник: [MultiplyMatrixToVector.java](src/main/java/com/mathpar/NAUKMA/stud2026/GR03/yermolovych/MultiplyMatrixToVector.java).

Размер матрицы `order=16`; вектор тоже содержит 16 элементов. При четырёх процессах `count=4`, `rootCount=4`. Ненулевой ранг `r` получает строки, начиная с `(r-1)*count`, а корень оставляет себе конец матрицы:

| Ранг | Строки матрицы при четырёх процессах |
| --- | --- |
| 1 | 0–3 |
| 2 | 4–7 |
| 3 | 8–11 |
| 0 | 12–15 |

Вспомогательный метод `rows(matrix,start,count)` берёт нужные строки из `matrix.M` и соответствующие индексы столбцов из `matrix.col`. Затем создаёт `MatrixS` с указанным числом строк и исходным числом столбцов. Это выделение блока строк, а не квадратного квадранта.

Корень отправляет работнику матричный фрагмент с тегом 1 и весь вектор с тегом 2. Работник принимает оба объекта и вызывает `a.multiplyByColumn(b.transpose(ring), ring)`. Преобразование вектора задаёт представление столбца, необходимое этому методу. Результат — вектор длиной, равной числу местных строк.

Ранг 0 вычисляет свои строки тем же методом. Затем `System.arraycopy` помещает локальные ответы в массив `Element[16]`: результат корня — начиная с `rootStart`, ответ работника `r` — с `(r-1)*count`. Для возвращаемого вектора тег равен рангу работника.

При трёх процессах `count=5`, `rootCount=6`: ранг 1 получает строки 0–4, ранг 2 — 5–9, корень — 10–15. Такая схема покрывает все 16 строк без пропусков и повторов. Данные работника не начинаются с `r*count`, потому что начальный блок тоже должен быть кому-то поручен.

Входы заданы как `A[i][j]=i+j+1`, `B[j]=j+1`. Поэтому первый элемент ответа — сумма квадратов от 1 до 16, то есть 1496. Каждая следующая строка матрицы больше предыдущей на единицу во всех позициях; сумма элементов вектора равна 136, поэтому `result[i]=1496+136*i`. Это даёт понятную ручную проверку полного ответа.

### MultiplyVectorToScalar Распределение элементов

Исходник: [MultiplyVectorToScalar.java](src/main/java/com/mathpar/NAUKMA/stud2026/GR03/yermolovych/MultiplyVectorToScalar.java).

Исходный вектор — `[-3,-2,-1,0,1,2,3,4]`, множитель — `NumberZ.valueOf(5)`. Число элементов `order=8`, допустимо от 1 до 8 процессов.

Формулы `count` и `rootCount` такие же, но расположение части корня отличается от предыдущего примера. Здесь он обрабатывает начало вектора `[0 ... rootCount-1]`. Работник `r` получает `count` элементов, начиная с `rootCount+(r-1)*count`.

При четырёх процессах каждый получает по два элемента. При трёх `count=2`, `rootCount=4`: корень обрабатывает первые четыре значения, ранг 1 — индексы 4–5, ранг 2 — 6–7. В обоих случаях фрагменты полностью покрывают исходный вектор.

Корень отправляет `Element[]` с тегом `100+r`. Работник умножает каждый свой элемент через `multiply(scalar,ring)` и возвращает массив с тем же тегом. Корень принимает ответ от указанного источника и копирует его на исходное место. Одинаковая метка в двух направлениях допустима: направление и источник приёма явно заданы.

Общий результат равен `[-15,-10,-5,0,5,10,15,20]`. Каждый элемент вычислен независимо, а сборка восстанавливает порядок индексов исходного вектора.

### Как построить рассказ на защите

Начать можно так: «Я распределяю матричные и векторные вычисления между MPI-процессами. Для каждого результата определяю необходимые входные блоки, передаю их через объектный транспорт Mathpar и собираю локально вычисленные части. Процесс 0 отвечает за распределение и сбор, но также выполняет собственную часть вычислений».

Сначала выпиши четыре формулы блоков произведения матриц. В `MatrixMul4` покажи одну из них через параметры `sendObjectArray` и `mmultiply`. Затем по таблице рангов объясни `MatrixMul8`, особенно направление нечётных результатов к чётным. В примере матрицы и вектора покажи формулы начала строк и место записи ответа. В последнем примере покажи, как корню достаётся остаток от деления длины.

Команды из корня проекта:

```bash
cd ~/paralel
./lab lab08
./lab lab08 mat4
./lab lab08 mat8
./lab lab08 matvec 3
./lab lab08 scale 3
```

Полные команды с classpath и фактический вывод находятся в комментариях Java-файлов. Сохранённые результаты находятся в [results](results/). Все четыре программы используют общую библиотеку Mathpar; её не требуется копировать в папку лабораторной.

Если спросят, что именно обеспечивает параллельность, покажи независимые локальные умножения после получения данных. Если спросят, зачем раздавать весь вектор при раздаче только части строк, укажи скалярное произведение каждой строки со всеми компонентами вектора. Если спросят, почему больше процессов не гарантирует выигрыш, объясни стоимость сериализации, передачи данных, сборки и ожидания наряду с арифметикой.
