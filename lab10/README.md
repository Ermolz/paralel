# Лабораторная 10

Решение случайной системы `A * X = B` методом Гаусса—Жордана с полным
выбором ведущего элемента. Строка «Завдання як у лаб.10» в задании
трактуется как ссылка на лабораторную 9.

Run:

```bash
cd ~/paralel
./lab lab10
```

Параметры: `./lab lab10 [processes] [N] [seed] [repeats]`.
По умолчанию: 4 процесса, `N = 4`, `seed = 2026`, один запуск каждого метода.
Число процессов равно `n * n`, `N` делится на `n`, `k = N / n`.
Каждый процесс хранит блок `k x k`; последний столбец блоков — `k x (k + 1)`.
Матрица и правая часть заполняются случайными `double` в диапазоне от 1 до 100.

В одном Java-файле находятся три варианта:

- `DIAGONAL` — диагональные ведущие элементы, алгоритм лабораторной 9.
- `ALL_GATHER` — каждый процесс передаёт свой максимум всем через `allGather`.
- `ROW_COLUMN` — максимумы собираются в последнем процессе каждой строки,
  затем обмениваются в последнем столбце и рассылаются по строкам.

Полный выбор ищет максимум **по модулю среди ещё не использованных строк
и столбцов A**. Столбец `B` в поиске не участвует. Первый локальный максимум
находится отдельной процедурой; следующие — непосредственно при обновлении
элементов блока. При равных модулях выбирается меньший номер строки, затем столбца.

На каждом процессе поддерживаются четыре списка: оставшиеся строки и столбцы,
выбранные строки и столбцы. После каждого шага ведущие индексы переносятся
в списки выбранных. Строки и столбцы физически не переставляются;
решение восстанавливается в исходном порядке неизвестных по выбранным индексам.
Нулевой, слишком малый (`abs(pivot) <= 1e-12`) или нечисловой ведущий элемент
завершает текущий метод с сообщением об ошибке, остальные методы выполняются.

Создаются отдельные коммуникаторы каждой строки и столбца сетки.
Коэффициенты исключения передаются по строкам, части ведущей строки — по столбцам.
Погрешность вычисляется по исходным данным: `P = A * X - B`, `max(abs(P[i]))`.
При `N <= 12` печатаются матрица, ведущие индексы, ранги, решение и невязка.

Сравнение времени:

```bash
./lab lab10 4 512 2026 5
```

При нескольких повторах сначала выполняются пять прогревочных запусков каждого
метода. Порядок методов меняется по кругу. Каждый запуск получает свежую копию
одного и того же блока. Время измеряется после `barrier` через `MPI.wtime`;
берётся максимум по процессам. В интервал входят поиск ведущих элементов,
исключение и сбор решения. Генерация, распределение исходной матрицы, копирование,
вычисление невязки и печать в интервал не входят.

Замеры от 2026-09-22: Intel Core i7-6900K, 8 физических ядер, 16 логических
процессоров; Ubuntu 24.04 в WSL, Java 21, OpenMPI 4.1.6. Использованы 4 MPI-процесса
с привязкой к разным ядрам, без переподписки. `N = 512`, пять измерений:

| Метод | Медиана времени, с | max(abs(P[i])) |
| --- | ---: | ---: |
| DIAGONAL | 0.064195 | 1.474639077514e-09 |
| ALL_GATHER | 0.112030 | 2.948752353404e-12 |
| ROW_COLUMN | 0.105368 | 2.948752353404e-12 |

В этой серии диагональный метод быстрее, а полный выбор уменьшил невязку.
Разница между временами двух вариантов полного выбора меньше разброса отдельных
замеров; универсального преимущества одного способа обмена эти данные не доказывают.
Первоначальные замеры с одним прогревом сохранены отдельно как `benchmark-initial-*`.

Вручную, без автоматических тестов, проверены `N = 1, 2, 4, 6, 512` на 1 или
4 процессах. Оба варианта полного выбора дали одинаковые ведущие элементы и `X`.
Проверены ведущие элементы вне диагональных блоков, восстановление порядка
неизвестных и отклонение несовместимого размера матрицы без зависания.
Выводы, даты замеров и привязка процессов сохранены в `results/`.
